# Lab 2 Part 2 - Stable Diffusion fine-tuning

This implementation uses `lambdalabs/naruto-blip-captions` and Stable Diffusion 1.5,
with exact dataset and model revisions recorded in the code/configuration. The
90/10 split is actually shuffled with seed 266 after deduplication. Two LoRA
ranks use the same data and update budget.

The first notebook cell sets up a locked, pinned runtime. It reuses a healthy
environment read-only; a damaged installation is bypassed with a fresh, uniquely
named environment. Two notebook installers cannot edit the same runtime at once.
Original notebooks, adapters and checkpoints are not deleted to repair packages.
On an RTX 4050, VAE
latents and CLIP text embeddings are cached before the UNet is loaded. This keeps
the VAE and text encoder out of training VRAM. Only LoRA parameters are optimized
with AdamW; a platform-sensitive 8-bit optimizer is not required. Generation uses
model CPU offload, batch one and VAE slicing/tiling, with the safety checker kept.

```bash
# From the repository root, the notebooks run these stages automatically.
python tools/setup_runtime.py --device cuda
# The first cell reads the actual interpreter from .lab2_runtime_cuda.json.
# Do not assume it is .venv when recovering a broken environment.
```

Edit `config.yaml` before starting if you need a different experiment. Both runs
must keep the same split and step budget. Changing a configuration for an existing
run is rejected. Old outputs from the previous trainer are renamed to a legacy
backup before a clean run starts. Completed compatible runs are not trained again.
Two complete checkpoints are retained per new run; incomplete checkpoints are
never treated as resumable. Losses, adapter parameter counts, GPU-hours and peak
allocated VRAM are recorded from the actual training process.

Ten in-domain evaluation prompts come from the held-out captions and are frozen
before training. The other ten cover out-of-domain and compositional requests.
Generation refuses to label base weights as a fine-tuned run if an adapter is
missing. KID, CLIP score and LPIPS are computed, not written as placeholder text.
There are 120 images, eight comparison grids, and CLIP nearest-training-image
checks for ten generations per run. Twenty in-domain samples make KID noisy.

If a code update changes the generation fingerprint (including the sampler,
prompts or adapter hashes), older images and their dependent metrics/reviews
are preserved under `outputs/generation_history/`. The program then generates
a consistent new comparison set. It does not change `output_root`, retrain,
delete adapters, or move the original training checkpoints. Matching generations
resume normally. `--fail-on-generation-change` requests the old stop-only behavior.

The code prepares 25 blinded image pairs, but at least three real people still
need to judge them. Their choices are not generated by the program. Upload models
and images to your team Hugging Face account after the real run.
